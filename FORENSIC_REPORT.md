# FORENSIC_REPORT.md — Secondary Renderer Stride Division Audit

## Executive Summary
This forensic audit identifies two secondary renderer files (`wallpaper_service.c` and `premium_signin_renderer.h`) that were still executing unconditional `/ 4` division on pixel strides, confirming why the 4X horizontal repeating strip artifact persisted in the second photograph.

---

## 1. Root Cause Findings

### Finding A: Unconditional /4 Division in wallpaper_service.c
- **Location**: [wallpaper_service.c](file:///d:/Signatures_OS/kernel/services/wallpaper/wallpaper_service.c#L151)
- **Code**: `uint32_t stride_pixels = fb_stride / 4;`
- **Bug**: `fb_stride` passed from `rook_render_flush` was `1920` (pixels). Executing `1920 / 4` forced `stride_pixels = 480`, causing the wallpaper canvas to draw with a 480-pixel pitch ($1920 / 480 = 4X$ horizontal repeat).

### Finding B: Unconditional /4 Division in premium_signin_renderer.h
- **Location**: [premium_signin_renderer.h](file:///d:/Signatures_OS/kernel/shell/rook/pages/premium_signin_renderer.h#L275)
- **Code**: `uint32_t stride_pixels = stride_bytes / 4u;`
- **Bug**: `stride_bytes` passed from `page_login.c` was `1920` (pixels). Executing `1920 / 4` forced `stride_pixels = 480`, causing the Sign-In UI to draw with a 480-pixel pitch ($1920 / 480 = 4X$ horizontal repeat).

---

## 2. Permanent Fix Plan
1. Update `wallpaper_service.c:151` and `premium_signin_renderer.h:275` to safely handle pixel vs byte stride:
   `uint32_t stride_pixels = (stride >= width * 4) ? (stride / 4) : ((stride > 0) ? stride : width);`
2. Add COM1 serial and LAN Debug telemetry in `page_login_on_render` to stream live runtime proof:
   `[LOGIN RENDER METRICS] width=1920 height=1080 stride=1920 stride_pixels=1920`
