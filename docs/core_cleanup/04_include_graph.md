# Include Graph Cleanup

## Problem
Currently, the `#include` paths in the OS look like a bowl of spaghetti. Many files use long relative jumps (`../../../something.h`), making the codebase extremely fragile when folders are moved.

## Cause
Headers were included on an as-needed basis without a unified include root or standard.

## Solution
1. Establish a firm include path policy based on the new boundaries.
2. Prefer forward declarations (e.g., `typedef struct BWE_Window BWE_Window;`) in header files over direct `#include` statements whenever possible to reduce compile-time coupling.
3. Clean up standard library dependencies. Core OS libs (`string.h`, `heap.h`) should be included uniformly.

## Risk
Missing a single include will cascade into hundreds of compilation errors.

## Verification
A clean compile is the ultimate proof. The `#include` graph generated by the compiler should form a Directed Acyclic Graph (DAG) with no backward loops.
